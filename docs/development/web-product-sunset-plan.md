# 无限画布网页版产品下线方案

> 状态：待确认方案，不代表已经实施。
>
> 2026-09-02 从 `multi-agent-project-mcp-plan.md` 的第九节、阶段 5、相关验收与风险条目拆出（小陈拍板）。与 MCP 接入没有依赖关系，可单独排期；MCP 接入期间不动 `web/`。

## 一、范围与盘点对象

- 仓库里与网页版 / 公网部署相关的东西：`Dockerfile`、`docker-compose.yml`、`docker-compose.local.yml`、`docker-entrypoint.sh`、`render.yaml`，以及 Go 后端（`main.go`、`handler/`、`router/`、`middleware/`、`service/` 等）中面向公网的登录、账号、云同步、后台管理部分。
- 不删：桌面 App 依赖的 `web/`（React/Next.js 在 Tauri WebView 中运行）、`127.0.0.1:3100` / `3101` 本机回环服务、本地项目、SQLite、本地媒体、导入导出。

## 二、产品层面的"完全去掉"

建议明确取消：

- 公网网页版入口
- 浏览器用户使用路径
- 网页版部署、宣传和发行说明
- 为远程网页访问开放的监听地址
- 桌面版不需要的云端托管承诺

## 三、不能直接删除的部分

当前 macOS App 的界面仍由 React/Next.js 在 Tauri WebView 中运行，本机拓扑依赖 `127.0.0.1:3100` 和 `127.0.0.1:3101`。因此不能直接删除 `web/`，否则桌面 App 的界面也会消失。

这里应区分：

- 网页版产品：删除。
- 桌面 App 内部使用的网页技术：暂时保留，仅允许本机回环访问。

## 四、分两步处理

第一步，先完成产品收口：

- 只发布 macOS App。
- 只绑定 `127.0.0.1`。
- README、安装说明和界面不再引导用户访问网页版。
- 停止公网部署与网页版测试矩阵。

第二步，在桌面版稳定后清理代码：

- 盘点登录、账号、云同步、Docker、后台管理和公网 API 中哪些仍被桌面版使用。
- 只删除确认不再依赖的部分。
- 保留本地项目、SQLite、本地媒体、导入导出和 WebView 界面。

## 五、实施阶段

- 关闭公网网页版与发布路径。
- 更新产品说明，只保留桌面 App。
- 盘点并分批清理桌面版不再依赖的 Web 业务代码。

通过标准：没有可对外使用的网页版入口；断网情况下桌面 App、MCP 和 CLI 仍能使用本地画布。

## 六、验收清单

- [ ] 不存在公网网页版入口，桌面 App 可离线打开本地画布。
- [ ] 断网情况下桌面 App、MCP 和 CLI 仍能使用本地画布。
- [ ] `web/` 与 3100 / 3101 回环服务仍在，桌面 App 界面正常。

## 七、风险与处理

| 风险 | 后果 | 处理方式 |
| --- | --- | --- |
| 过早删除 `web/` | 桌面 App 无界面 | 先删除网页版产品入口，再按依赖盘点清理代码 |
| 误删桌面版仍在用的后端接口 | 本地功能失效 | 第二步逐项盘点依赖，只删确认无依赖的部分 |

## 八、未知

- "去掉网页版"最终是否还包括删除账号、云同步、Docker 和后台管理代码。本方案默认先取消浏览器产品与公网部署，不直接删除桌面 App 仍依赖的内部前端代码。
