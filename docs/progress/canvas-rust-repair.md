## 正式保存误报的根因与修复

第一次 Rust 安装后，窗口显示“桌面已有较新的修改”。待确认保存与 SQLite 读回之间只有一个坐标小数不同：`222.56302150354014` 被默认 JSON 解析变成 `222.56302150354017`。这使成功落盘后的内容核对误报冲突。

桌面、adapter、API 三处启用 `serde_json/float_roundtrip`。新增回归直接从外部小数字面量进入保存、SQLite 重开、版本预览和 IPC 序列化；修改前出现一位浮点差异，修改后通过。前端还补上“数据已落盘但回执丢失”的精确确认：只有全部内容字段完全相等才确认恢复记录；并发新编辑仍保留并提示冲突。

第二次安装前正常退出 App，再备份 App 数据和 WebKit。针对已证明的唯一小数误差，使用当前内容哈希校验后原子修正该坐标，没有修改其他字段或时间。重新构建、安装、启动后，正式窗口显示“已保存”；版本历史按钮并入同一状态栏，消除初装发现的布局重叠。修正前后哈希、差异和回归日志留在私有证据目录。
