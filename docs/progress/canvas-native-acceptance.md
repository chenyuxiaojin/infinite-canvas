## 平移诊断结论与性能边界

正式临时诊断包仅在隔离项目显式启用，20秒、最多120条、只记录事件状态/坐标/视口，内存保存。事件行为未修改，异常记录后原样抛出。正式AX读回见`native-pan-events.json`：

1. 工具为pan，Space=false，排除区域=false。
2. pointerdown为button=0、buttons=0、pointerType=mouse。
3. setPointerCapture成功。
4. 首pointermove为buttons=0、panning=true，触发已有“鼠标松开”保护，提交未改变的视口0,0。
5. 后续move已panning=false；没有Space/blur/capture异常。

因此该次CUA自动drag交付的按钮状态不是持续按住，足以解释不移动。**本问题是自动输入与平移保护条件不匹配的实测证据，不是已证明的产品鼠标故障。** 没有删除buttons=0保护，也没有为自动化改鼠标行为。真实组件事件6项测试进一步确认held buttons=1可移动，其他终止路径符合实现。

临时诊断已停止，源码与插桩前逐字恢复；普通包已按正常build:app构建安装并启动。正式隔离项目没有诊断入口，包内诊断标识匹配0。安装前后的App ZIP及数据/WebKit备份保留私有目录。诊断期间的数据不作为性能基线。

原生缩放100%→44%已实测，真实人物图和连线正确显示；节点拖动/成组/越界通过。当前CUA接口未提供另一种能保证held buttons的原生拖动方式，故持续原生pan与FPS仍不升级为通过，也不绕过工具换系统输入方式。
